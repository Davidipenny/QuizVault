# QuizVault 本地电脑版技术方案

## 总体方案

首期实现 Windows 本地桌面应用，覆盖六类题型、题库管理、完整刷题闭环及批量导入。采用“本地 Web 应用封装为桌面程序”的架构，为后续部署网页版保留同一套前端、接口和数据模型。

- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus。
- 本地后端：FastAPI、Pydantic、SQLAlchemy 2、Alembic。
- 本地数据库：SQLite，启用外键、WAL 和事务。
- 桌面外壳：pywebview，使用 Windows WebView2；PyInstaller 打包为安装包。
- 本地服务只监听 `127.0.0.1`，启动器自动选择端口并注入临时访问令牌。
- 数据放在 `%APPDATA%\QuizVault\`，支持自动备份、手动导出和恢复。
- 后续网页版继续使用 Vue 和 FastAPI，将 SQLite 替换为 PostgreSQL，并加入登录、团队空间、对象存储和 HTTPS。

现有 Tkinter 页面不继续扩展；复用其中经过测试的 Markdown 解析、题目校验、错题/收藏和刷题规则，重构为独立领域服务。

## 功能与页面

桌面端包含以下主页面：

- 题库中心：新建、修改、删除、合并、标签、题数统计和最近学习记录。
- 题目管理：分页、搜索、题型筛选、单题编辑、批量删除、跨题库移动或复制。
- 录题中心：手工录题、文本导入、Excel 导入、Word 导入、AI JSON 粘贴导入。
- 刷题设置：题目范围、题型、顺序/随机、选项乱序、背题模式、自动切题、答案比对和夜间模式。
- 刷题页面：进度、上一题回顾、收藏、笔记、纠错标记、答案解析、字体调节和中断恢复。
- 学习记录：错题、收藏、笔记、未做题、历史答题记录和正确率统计。
- 迁移向导：导入现有 `banks/` 目录及其错题、收藏、标记和刷题进度。

首期不实现依赖联网运营的广告、题库分享、题库更新、模拟考试排名和巅峰挑战；数据模型为这些能力预留扩展空间。

## 数据模型与规则

所有实体使用 UUID，避免现有“题号 + 题型”组合键冲突。主要实体包括：

- `workspaces`、`users`：本地版自动创建固定用户和空间，网页版直接扩展为多用户。
- `question_banks`：名称、介绍、标签、挑战题数、版本和归档状态。
- `questions`：题型、题干、案例材料、解析、来源、排序、内容指纹和版本。
- `choices`：选项标签、内容、正确标记和显示顺序。
- `study_states`：错题次数、收藏、笔记、标记、最近作答和掌握状态。
- `quiz_sessions`、`quiz_answers`：刷题配置、题目顺序、当前进度及每题答案快照。
- `collections`、`collection_questions`：支持多个自定义收藏夹。
- `import_jobs`、`import_errors`：导入预览、错误定位、提交状态和统计。

六类题型采用统一 `answer_spec`：

- 单选：唯一正确选项。
- 多选：至少两个正确选项，按集合完全一致判分。
- 任意选：一个或多个正确选项，不提示正确选项数量，按集合完全一致判分。
- 判断：布尔答案。
- 填空：支持多个空、每空多个可接受答案及“答案无序”。
- 问答：保存参考答案；默认展示后由用户自评，开启答案比对时进行规范化文本比较并允许手动修正结果。

文本比较统一处理首尾空白、全角空格和换行；不默认忽略标点或进行语义判分，避免错误自动评分。

## 接口与导入

前后端统一使用 `/api/v1` JSON 接口：

- `/banks`、`/banks/{id}/questions`：题库和题目 CRUD、搜索、分页、合并。
- `/imports/preview`、`/imports/{id}/commit`：解析预览、校验、去重和事务提交。
- `/quiz-sessions`、`/quiz-sessions/{id}/answers`：创建刷题会话、提交答案和恢复进度。
- `/study-states`、`/collections`：错题、收藏、笔记和标记管理。
- `/migration/legacy/preview`、`/migration/legacy/commit`：旧版数据迁移。

导入流程固定为“选择来源 → 解析预览 → 行级校验 → 用户修正或排除 → 事务保存”：

- Excel：支持 `.xlsx` 和 `.xls`，按题干、答案、解析、选项列解析；提供标准模板。
- Word：支持 `.docx` 模板格式，按题型标题和连续题号分组。
- 文本：分别提供选择、任意选、判断、填空、问答解析器。
- AI 导题：首期仅接收截图所示 JSON，不直接调用付费模型。
- 使用 `题型 + 规范化题干 + 规范化选项` 的 SHA-256 指纹在同一题库内去重。
- 单次默认限制 3000 题；提交过程全量成功或全量回滚，并可导出错误报告。

## 迁移、测试与验收

旧版迁移先生成只读报告，再备份新数据库并提交；原 Markdown/JSON 文件始终不修改。迁移建立旧组合键到新 UUID 的映射，迁移题目、错题次数、收藏夹、标记和可解析的进度。无法匹配的记录列入报告，迁移操作可重复执行且不会产生重复数据。

测试覆盖：

- 六类题型校验、判分、乱序和文本规范化。
- Markdown、文本、Excel、Word、AI JSON 的正常与异常样例。
- 导入去重、事务回滚、题库合并和并发提交幂等性。
- 旧数据完整迁移、缺失题目、重复 ID 和损坏 JSON。
- 刷题范围筛选、进度恢复、错题增减、收藏与笔记。
- Vue 组件测试和 Playwright 完整流程测试。
- Windows 安装、启动、退出、数据库备份及无网络运行冒烟测试。

验收主流程为：迁移旧题库 → 导入六类题目 → 设置刷题范围 → 中断并恢复 → 生成错题/收藏/笔记 → 搜索和重新练习 → 导出备份。未来上云时，前端仅切换 API 地址，后端迁移 PostgreSQL 并增加认证，不重写核心业务。

## 实施顺序

1. 建立领域模型、SQLite 迁移、统一题型校验和判分引擎。
2. 完成题库、题目管理及旧版迁移向导。
3. 完成六类题型编辑器和四种批量导入方式。
4. 完成刷题设置、答题、进度、错题、收藏和笔记。
5. 完成统计、备份恢复、桌面封装和 Windows 发布验证。
6. 后续云端阶段增加 PostgreSQL、账号登录、空间权限、同步冲突处理和部署流水线。

## 默认假设

- 首期仅支持 Windows 10/11，不依赖外网即可使用。
- 产品面向个人和小团队，但本地版采用单用户模式，不实现实时协作。
- 本地数据库为唯一事实来源；Markdown/Excel/Word 是导入导出格式，不再承担运行时存储。
- AI 导题首期不内置模型调用，避免 API 密钥、费用和隐私问题。
- 现有 Tkinter 版本保留为只读兼容版本，迁移完成前不删除旧数据。
