# QuizVault v2 计划达标改进方案

## 总结

修复会导致备份不可用、旧数据丢失和多空填空无法作答的问题，补齐背题模式、未做题记录、认证下载、数据库迁移、请求模型、自动化测试及 Windows 安装验证。保留现有 Vue、FastAPI、SQLite 和 pywebview 架构，不重写已经可用的 CRUD 与判分逻辑。

## 实施步骤

### 1. 数据安全与数据库迁移

- 将 `create_backup()` 改为 SQLite Online Backup API：从活动数据库连接备份到临时文件，执行 `PRAGMA quick_check` 后原子重命名，确保 WAL 中的数据一并保存。
- 恢复前验证文件头、`quick_check`、必要表和数据库版本；先用新备份实现保存当前数据库，再执行恢复。
- 不删除现有 4096 字节损坏备份，但在备份列表中标记为无效并禁止恢复。
- 启动时改为运行 Alembic，不再使用 `Base.metadata.create_all()` 作为升级机制。
- 将 `0001` 固化为明确的基线表结构；检测到旧数据库有业务表但没有 `alembic_version` 时先 stamp 到 `0001`，再执行后续迁移。
- 新增迁移创建独立 `import_errors` 表，并把新导入任务的行级错误写入该表。
- 将 `alembic.ini` 和迁移目录加入 PyInstaller 资源，开发版和打包版使用同一升级入口。

### 2. 旧版迁移正确性

- 题库加载逻辑与旧版 `_load_bank_questions()` 对齐：支持 Markdown 和 JSON，按题型与规范化题干去重，并应用 `deleted.json`。
- 使用稳定的 `目录 + 来源 + 旧题号 + 题型` 映射键，不再依赖解析数组下标。
- 兼容 `wrong_books`、旧式 `wrong_questions`、两种 `collections` 结构、`flagged` 和 `quiz_progress`。
- 多个错题本引用同一题目时保留最大 `wrong_count`；无法匹配的记录逐项进入迁移报告。
- 预览阶段同时分析题目、错题、收藏、标记和进度，显示可迁移、无效、重复、已迁移及无法匹配数量。
- 提交阶段先创建有效备份，再在单一事务中迁移；重复执行不得新增题目、状态、收藏关系或会话。
- 修正进度题目顺序和答案快照映射，确保过滤无效或已删除题目后不会把答案关联到另一题。

### 3. 刷题闭环与页面功能

- 普通会话题目响应新增不泄露答案的 `answer_meta`，填空题至少返回 `blank_count` 和 `unordered`；前端据此生成正确数量的输入框。
- 普通模式不返回 `answer_spec` 或选项 `is_correct`；提交答案后才返回参考答案和解析。
- 背题模式下，获取会话时返回参考答案和解析，并在提交前提供“查看答案”操作；查看答案不自动记录作答。
- 学习记录增加“未做题”标签。后端通过题目与学习状态左连接返回从未作答的题目，支持题库筛选和分页。
- 统一受保护下载 URL 生成函数，将临时 token 附加到 Excel 模板和备份下载地址。
- 对答案提交增加幂等处理：重复提交同一题只更新答案记录，并根据前后结果差异调整错题次数，避免网络重试重复累计。
- 导入提交在 SQLite 下使用 `BEGIN IMMEDIATE` 串行化同一任务；第二个并发请求读取首个请求的提交结果，不重复插入。

### 4. API 契约与校验

- 为题库、题目、导入、会话、答案、学习状态、收藏和恢复请求建立 Pydantic 模型，禁止未知字段。
- 校验名称非空、题型枚举、分页范围、非负错题次数、题目范围、会话状态和备份大小。
- 题目模型使用按题型区分的 `answer_spec`，保持现有 JSON 字段兼容，不改变数据库中的六类题型名称。
- API 保持 `/api/v1` 路径兼容；新增字段包括 `answer_meta` 和迁移预览统计，不移除现有响应字段。
- 导入编辑时重新计算指纹、同批重复和库内重复，错误报告支持 JSON 下载。

### 5. 测试与 Windows 发布

- 后端增加：WAL 备份与恢复、损坏备份、现有数据库 Alembic 升级、六类题型异常输入、并发导入、重复答案提交测试。
- 使用从旧版真实格式裁剪的固定测试夹具覆盖 `wrong_books`、两种收藏结构、标记、进度、JSON 题库、删除记录、重复 ID 和损坏 JSON。
- Vue 组件测试覆盖多空填空、背题模式、未做题列表、导入修正/排除和认证下载 URL。
- 增加 Playwright，使用独立临时数据库完成：迁移旧题库、导入六类题、开始刷题、中断恢复、生成错题/收藏/笔记、未做题筛选、备份导出与恢复。
- 扩展打包冒烟测试，验证临时 token、静态资源、数据库初始化、备份内容和无网络启动。
- 使用 Inno Setup 生成 `QuizVault-Setup.exe`；安装包包含 PyInstaller 程序和离线 WebView2 Runtime 安装程序。
- 在 Windows 10、Windows 11 各执行一次安装、启动、退出、重启恢复、备份恢复和断网运行检查。

## 验收标准

- 新备份包含当前所有题库和题目，`quick_check` 通过，并可恢复到全新数据目录。
- 真实旧版夹具中的题目、错题次数、收藏、标记和可解析进度全部迁移；无法匹配数据在预览中可见。
- 两空及以上填空题显示正确数量的输入框并能正确判分。
- 背题模式可在提交前查看答案；普通模式提交前不暴露答案。
- 学习记录可以查看和筛选未做题。
- Excel 模板和备份在桌面 token 模式下均可下载。
- Alembic 能初始化空库并升级没有版本表的现有数据库。
- 后端测试、Vitest、Playwright、前端构建、PyInstaller 和安装包冒烟检查全部通过。

## 实施顺序与提交边界

1. 先修复备份并补回归测试，确认后再进行任何迁移或恢复测试。
2. 修复旧版加载、状态映射和迁移报告。
3. 修复多空填空、背题模式、未做题及认证下载。
4. 引入 Pydantic、`import_errors` 和 Alembic 启动升级。
5. 补齐并发幂等、完整自动化测试和 Windows 安装包。
6. 每一步独立提交；最后重新执行计划中的完整验收主流程。

## 假设

- 目标是完整满足原技术方案，而不只修复三个最高优先级缺陷。
- 保持现有 SQLite 数据和 API 路径向后兼容。
- 现有损坏备份不自动删除，避免未经确认的数据操作。
- 构建安装包时允许下载并固定 WebView2 Runtime；最终安装和运行不依赖网络。
- 开始实施前先重新运行 `pnpm install --frozen-lockfile`，恢复当前不完整的生成目录 `web/node_modules`。
